# Implementation and anatomy

## Start from the retained application

`assets/source/index.html`, `assets/styles.css`, `assets/app.js`, loader and compressed anatomy chunks preserve the finished Pterional Craniotomy website. Use `materialize_site.py` to copy it into a new project and expose editable `src/index.html`, `src/app.js` and JSON data. `baseline/` is the intact runnable reference, and `adaptation-status.json` identifies the original case. This baseline includes reference anatomy; it is not an atlas of every body region. Its renderer, CSS, six anatomy chunks, manifest, loader and `tools/anatomy_build/` come from PR #1. Read [the reuse map](lifelike-reference.md); preserve the actual implementation and data fields instead of recreating a visual approximation. For any new operation, compare the result side by side with `baseline/` at the same viewport, palette, camera and step phase. Match the page's arrangement, styling, shader and controls; adapt only procedure-dependent content and geometry.

Choose a destination path that does not yet exist; the helper refuses to overwrite even an empty directory. The script uses the chunk count declared on the reference loader tag, checks the pinned chunks and mesh count, and inlines the reference CSS for the packager. The runtime reads either the hosted payload or the standalone data tags. It leaves the `<!-- GUIDE_DATA -->` and `<!-- GUIDE_RUNTIME -->` insertion markers in the editable HTML. The build helper reads `data/*.json`, renders the offline file, and produces a compressed static site and root-index ZIP. It does not infer a new operation from a procedure name. Do not use a successful unmodified reference build as a finished new procedure.

## Geometry and source provenance

Use suitable native atlas geometry for the actual region. The bundled head subset can serve new cranial guides only where its source structures are actually appropriate. For spinal or other procedures, obtain a relevant licensed dataset or supplied anatomical meshes; do not stretch a skull or rename a vessel into another organ. Discover local atlases before downloading again. The `atlas-tools` folder has a PDF extractor, `.blend` catalog and fallback reader; consult its anatomy notes and adapt to the actual source format. It does not include an entire atlas. Missing source geometry remains a specific gap until resolved.

Preserve saved object world transforms followed by one common region transform and explicit units/axes. Verify winding, normals, triangle indices and all finite values. Native left structures are preferable to mirrored right structures. Added illustrative tissues may be mirrored only where appropriate; fit membranes independently to the native anatomy on each side. Record source IDs, transformation and whether each addition is native, reconstructed or schematic.

Do not fabricate clinical registration from an atlas. Named exact distances, bone landmarks and small deep apertures need source support and anatomical registration. When a segmentation lacks the required specificity, create an honest schematic illustration or identify the omission. Do not label a broad skull-base object as a separately reconstructed optic canal or strut.

## Physical depth and tissue fit

Use opaque, depth-tested surfaces with depth writes. Preserve actual geometric depth in every view: intact muscle lies outside intact bone, dura inside bone, and cortex inside dura where those tissues anatomically apply. A procedurally removed surface exposes what is underneath. Do not force a fixed semantic draw order that makes anatomy appear on top when rotated. Avoid transparency/sorting fixes that permit brain to show through intact bone. Inspect the full atlas context as well as the smaller operative subset.

Make openings and membranes clean, with stable borders and intentional thickness. Fit original fascia/fat layers to the actual muscle envelope and respect the correct lamina sequence. A superficial muscle elsewhere in the region must not be mistaken for the relevant deep temporalis or paraspinal envelope. Sample clearance at vertices and triangle interiors against the full nearby native cortex/bone or other surrounding structures on both sides; close rims and check for intersections. Sampling is useful evidence, not a continuous intersection proof.

Synchronize display, picking, highlight and label retention masks. A removed region must not remain pickable or anchor a label. Avoid stale pixel buffers and high-DPI coordinate errors. Keep the stable one-label box, local visible anchors and separate depth-aware picking framebuffer. For markers on a surface, use a small documented offset to prevent z-fighting, not a large floating trajectory. Never move all native anatomy to make labels or tools fit.

Fit membranes to the appropriate native atlas anatomy. The retained pterional dura is the PR #1 surface fitted beneath the inner table. Keep its source limits. Preserve the illustrative skin/subcutaneous slab, galea, loose areolar gap and pericranium, the progressive incision, flap peel and separate galeal/skin closure. Check layer fit and deformed boundaries on both sides. Adapt or omit a tissue only when the new procedure and evidence justify it; never replace these working features with incision lines alone.

## Time and branch behavior

Represent the procedure as cumulative state plus a current transition. A new step retains completed openings or displaced tissues. Before excludes the current transition, not all history. Closure reverses the appropriate opening/displacement while permanent resections stay removed. Place extradural work before dural opening and intradural work after it only when these are actually the new case's supported variants. Tools and trace markers should appear at their corresponding stages, disappear when unrelated, and follow the selected native side and the tissue they act on.

Reuse the PR's curl/peel vertex shader and matching JavaScript `curlPoint` for scalp, pericranial, fascial, temporalis and dural flaps, including the drape table and complementary stationary/moving passes. Preserve the flap contract and synchronize deformed normals, picking, labels and depth sorting. Adapt hinge, radius, lift, timing and native-side fit using the new case's evidence. Preserve the separate bone-flap travel. Sample intermediate poses and reverse closure paths; these hinges are illustrative, not biomechanical simulations. Avoid openings that expand from the center to depict a removed flap. Use color highlights on the changed region and recommend a useful view without involuntarily replacing the user's current camera. Provide a clear full-context action when an isolated deep view is useful; describe the isolation as a display choice rather than additional tissue removal.

Set one immutable orbit pivot at the midpoint of the stable native anatomy bounds in model coordinates. Use the cranial vault for skull procedures and the full displayed vertebral span for spine procedures. Use this point for every view and gesture, independently of the patient positioning hinge, visible layers, side, step or surgical target. Room framing transforms the orientation along with the patient pose around the same model-space pivot. Copy the Pterional PR #1 trackball, view-space pan and lens zoom as a unit. Apply pan before perspective division in both the vertex shader and CPU projection for picking and labels. Convert drag deltas using the current distance, zoom and viewport height so the pivot moves with the pointer during intentional panning.

Route all orientation presets to the shared camera setter. Clear pan immediately on Anterior, Left, Right, Posterior, Top, Surgeon’s View, Recommended View, Reset View and Focus Change. Use `overviewCamera()` to read the first step’s camera for the current configuration and side. Give that camera an explicit distance that frames the complete skull or displayed spine at launch, with an overview magnification that fits on desktop and mobile. Reset View and Home restore its orientation, distance and magnification while preserving the step, progress, patient pose and layers. Route directional presets through its distance and magnification, with their own angles. Keep Recommended View and Focus Change as the separate entry points for step-specific detail. Give Surgeon’s View a procedure-specific angle and explicit distance and magnification that frame the intended anatomy around the fixed pivot. A plain drag uses the same incremental quaternion turn about a screen-plane axis from every orientation. Alt/Option-drag, Q/E and two-finger twist apply explicit roll. Shift/right-drag and touch midpoint movement pan, while pinch, wheel and plus/minus adjust the lens. Keep the patient pose and step playback separate from Surgeon’s View.

Use the radial five-pixel press threshold. Hold canvas resolution and shader quality steady throughout interaction. Skip the picking pass and readback while dragging, resume after the final release or cancellation, and keep click picking immediate. Preserve complete camera state through ordinary step changes and 2D capture. See [geometry and clearance](geometry-and-clearance.md) for sampled visibility, including adapted configurations and lateralities.

## Packaging

`build_site.py` creates:

- `<slug>-anatomy-guide.html`: standalone offline page with embedded data/runtime;
- `site/index.html` and `site/assets/`: buildless hosted files;
- `<slug>-netlify.zip`: deployable contents with `index.html` at the ZIP root.

Data compression is lossless and split into 7 MiB pieces by default. Use current hosting documentation if destination limits matter. Keep website runtime assets in this ZIP; optional large GLB libraries, PDFs and working files belong in a separate study bundle. Do not discard needed geometry to shrink the upload without the user's request. The reference and generated hosted sites use the same loader. It streams the ordered chunks into the browser’s gzip decoder, reports progress and validates the mesh count. The hosted loader tag records the build’s chunk and mesh counts. Check decoded data against source data. Revalidate new/deployment-specific code; the reference's prior checks do not prove a changed case works.

## Added assets

Put new local image, font, audio or video assets under project `static/`, with paths matching their site URL (for example `static/assets/plane.svg` is `assets/plane.svg`). The build helper copies these files into the hosted site and embeds matching references in the offline HTML, runtime and JSON data. The reference keeps its upstream external CSS; materialization inlines it verbatim. Keep adapted frontend code/styles inline in `src/index.html` and `src/app.js`; do not add unbundled module/CSS/script dependencies. Source assets outside this documented folder or unknown relative dependencies must be embedded explicitly or resolved before building. Do not store anatomy PDFs or secrets in `static/`, which is public deployment content.

Exact quoted media URLs (including literal backtick strings) and root-relative media URLs can be embedded. Computed/dynamic asset paths must be resolved to embedded data explicitly; do not assume the packager can evaluate JavaScript. Publish only the generated `site/` directory, never the whole working project or its private `baseline/`, evidence or PDF folders.

## Retained mobile implementation

At widths up to 760 px the reference uses `100dvh`, a dynamically measured reading row and a flexible model row. `syncMobileLayout` moves existing layer/reset controls into `mobileModelDock` and the existing pager into `mobileStepNav`; it restores their desktop homes above that breakpoint. `updateMobileReaderHeight` measures a hidden active-card probe containing the title and first two sentences. `alignActiveStep` adjusts only the guide panel scroll position, and mobile bottom padding permits the last card to align. A layout ResizeObserver and resize handler recompute the allocation. The upward menu is aligned to the dock rather than its narrower summary, and its viewport budget has no artificial minimum. Default mobile labels are disabled independently of desktop preference, while explicit selection remains available. Adapt these mechanisms for the new case without reintroducing the removed mobile title/status/preset controls. These are source and software-test observations; actual phone rendering still needs permitted browser/device inspection.

The deployment ZIP is the public runtime, not the editable working project. If an editable source archive is requested, package `src/`, `data/`, `static/`, attribution and adaptation metadata separately. Keep private research/PDFs out of public deployment archives.
